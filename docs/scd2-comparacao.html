SCD2 com e sem função

O mesmo carregador Go tem duas implementações das regras SCD Tipo 2. A flag -strategy escolhe qual roda. Extração, COPY, staging, guardas, transação e log são comuns; só o passo 5 muda.

-strategy funcao · MERGE em PL/pgSQL -strategy sem-funcao · queries sqlc

Onde as duas se separam

  1. 1
    Advisory lock

    pg_advisory_xact_lock impede duas cargas simultâneas.

  2. 2
    TRUNCATE da staging

    Staging UNLOGGED, com row_hash gerado pelo banco.

  3. 3
    Extração em pipeline + COPY binário

    Keyset na origem numa goroutine; :copyfrom do sqlc na staging.

  4. 4
    Guardas

    Origem vazia ou exclusões acima de -max-delete-pct abortam com código 3.

5
Com função
Uma chamada: SELECT dw.scd2_merge_sales_territory($1)

Dentro da função: ANALYZE, um MERGE que fecha, insere e marca exclusões, e o INSERT em dw.etl_log. Depois, o Go lê o log.

5
Sem função
Quatro comandos sqlc, em ordem, mais o log

ANALYZE → ExpireChanged → CloseDeleted → InsertNewVersions → InsertEtlLog. O Go soma as contagens e confere que cada versão fechada ganhou uma nova.

  1. 6
    COMMIT

    A restrição “uma versão atual por chave” (EXCLUDE … DEFERRABLE) é checada aqui, nas duas.

Sem funçãointernal/scd2/sem_funcao.go

O Go orquestra os passos. A ordem importa: o INSERT depende de os UPDATEs já terem fechado as versões.

// applyWithoutFunction aplica as regras SCD2 na ordem:
// fechar alterados -> fechar excluídos -> inserir o que ficou sem versão atual.
// A ordem importa: o INSERT depende dos UPDATEs já terem fechado as versões.
func applyWithoutFunction(ctx context.Context, tx pgx.Tx, q *dw.Queries, staged int64) (dw.DwEtlLog, error) {
	// Estatísticas frescas da staging recém-carregada. ANALYZE não é uma
	// query que o sqlc gere, então vai direto pela transação.
	if _, err := tx.Exec(ctx, "ANALYZE dw.stg_sales_territory"); err != nil {
		return dw.DwEtlLog{}, fmt.Errorf("analyze staging: %w", err)
	}

	expiradas, err := q.ExpireChanged(ctx)
	if err != nil {
		return dw.DwEtlLog{}, fmt.Errorf("fechar versões alteradas: %w", err)
	}
	excluidas, err := q.CloseDeleted(ctx)
	if err != nil {
		return dw.DwEtlLog{}, fmt.Errorf("fechar excluídas: %w", err)
	}
	ins, err := q.InsertNewVersions(ctx)
	if err != nil {
		return dw.DwEtlLog{}, fmt.Errorf("inserir versões: %w", err)
	}

	// Invariante: toda versão fechada por mudança ganha exatamente uma nova.
	if int64(ins.NovasVersoes) != expiradas {
		return dw.DwEtlLog{}, fmt.Errorf("inconsistência: %d versões fechadas, %d novas versões",
			expiradas, ins.NovasVersoes)
	}

	logRow, err := q.InsertEtlLog(ctx, dw.InsertEtlLogParams{
		Processo:     ProcessName,
		LinhasOrigem: int32(staged),
		Novas:        ins.Novas,
		NovasVersoes: ins.NovasVersoes,
		Reativadas:   ins.Reativadas,
		Expiradas:    int32(expiradas),
		Excluidas:    int32(excluidas),
	})
	if err != nil {
		return dw.DwEtlLog{}, fmt.Errorf("gravar etl_log: %w", err)
	}
	return logRow, nil
}

Com funçãodb/migrations/002_scd2_funcao.sql

A regra inteira mora no banco. O sqlc enxerga só a chamada (db/dw/query.sql, seção COM FUNÇÃO):

-- name: MergeSalesTerritory :one
SELECT dw.scd2_merge_sales_territory(sqlc.arg(processo)::text)::bigint AS log_id;

-- name: GetEtlLog :one
SELECT * FROM dw.etl_log WHERE id = $1;
CREATE OR REPLACE FUNCTION dw.scd2_merge_sales_territory(p_processo TEXT)
RETURNS BIGINT
LANGUAGE plpgsql
AS $$
DECLARE
    v_ts     TIMESTAMPTZ := now();  -- instante da transação: fecha e abre versões no mesmo ponto
    v_origem INT;
    v_id     BIGINT;
BEGIN
    -- Estatísticas frescas da staging recém-carregada para o planner
    ANALYZE dw.stg_sales_territory;

    SELECT count(*) INTO v_origem FROM dw.stg_sales_territory;
    IF v_origem = 0 THEN
        RAISE EXCEPTION 'staging vazia: carga abortada para não fechar a dimensão inteira';
    END IF;

    -- historico: chaves que já existiam na dimensão, lidas UMA vez.
    -- MATERIALIZED é necessário: um EXISTS correlacionado sobre a dimensão
    -- pode virar Seq Scan repetido por linha (quando as estatísticas dizem
    -- que ela está vazia, p.ex. após TRUNCATE + VACUUM), e cada repetição
    -- percorre também as páginas que o próprio MERGE acabou de inserir:
    -- custo quadrático (1 milhão de linhas: minutos em vez de segundos).
    WITH historico AS MATERIALIZED (
        SELECT DISTINCT sales_territory_id FROM dw.dim_sales_territory
    ),
    resultado AS (
        MERGE INTO dw.dim_sales_territory AS t
        USING (
            SELECT s.sales_territory_id AS merge_key,
                   s.sales_territory_id, s.region, s.country, s."group", s.row_hash,
                   CASE WHEN h.sales_territory_id IS NOT NULL
                        THEN 'REATIVADA' ELSE 'NOVA' END AS tipo
            FROM dw.stg_sales_territory s
            LEFT JOIN historico h ON h.sales_territory_id = s.sales_territory_id

            UNION ALL

            SELECT NULL::INT,
                   s.sales_territory_id, s.region, s.country, s."group", s.row_hash,
                   'NOVA_VERSAO'
            FROM dw.stg_sales_territory s
            JOIN dw.dim_sales_territory d
              ON d.sales_territory_id = s.sales_territory_id
             AND d.is_current
            WHERE d.row_hash <> s.row_hash
        ) AS s
            ON  t.sales_territory_id = s.merge_key
            AND t.is_current

        -- Mudou: fecha a versão atual
        WHEN MATCHED AND t.row_hash <> s.row_hash THEN
            UPDATE SET valid_to   = v_ts,
                       is_current = FALSE

        -- Nova chave, reativação ou nova versão
        WHEN NOT MATCHED BY TARGET THEN
            INSERT (sales_territory_id, region, country, "group", row_hash,
                    valid_from, is_current, is_deleted)
            VALUES (s.sales_territory_id, s.region, s.country, s."group", s.row_hash,
                    v_ts, TRUE, FALSE)

        -- Sumiu da origem: fecha e marca exclusão (só a versão atual)
        WHEN NOT MATCHED BY SOURCE AND t.is_current THEN
            UPDATE SET valid_to   = v_ts,
                       is_current = FALSE,
                       is_deleted = TRUE

        RETURNING merge_action() AS acao,
                  s.tipo         AS tipo,
                  new.is_deleted AS excluida
    )
    INSERT INTO dw.etl_log (processo, inicio, fim, linhas_origem,
                            novas, novas_versoes, reativadas, expiradas, excluidas)
    SELECT p_processo, v_ts, clock_timestamp(), v_origem,
           count(*) FILTER (WHERE acao = 'INSERT' AND tipo = 'NOVA'),
           count(*) FILTER (WHERE acao = 'INSERT' AND tipo = 'NOVA_VERSAO'),
           count(*) FILTER (WHERE acao = 'INSERT' AND tipo = 'REATIVADA'),
           count(*) FILTER (WHERE acao = 'UPDATE' AND NOT excluida),
           count(*) FILTER (WHERE acao = 'UPDATE' AND excluida)
    FROM resultado
    RETURNING id INTO v_id;

    RETURN v_id;
END;
$$;
Sem funçãodb/dw/query.sql · seção SEM FUNÇÃO

Cada passo é uma query tipada pelo sqlc, versionada junto com o Go.

-- name: ExpireChanged :execrows
-- Passo 1: fecha a versão atual das chaves cujo hash mudou.
UPDATE dw.dim_sales_territory AS d
SET valid_to   = now(),
    is_current = FALSE
FROM dw.stg_sales_territory AS s
WHERE d.sales_territory_id = s.sales_territory_id
  AND d.is_current
  AND d.row_hash <> s.row_hash;

-- name: CloseDeleted :execrows
-- Passo 2: fecha e marca como excluída a versão atual das chaves que
-- sumiram da origem.
UPDATE dw.dim_sales_territory AS d
SET valid_to   = now(),
    is_current = FALSE,
    is_deleted = TRUE
WHERE d.is_current
  AND NOT EXISTS (SELECT 1 FROM dw.stg_sales_territory s
                  WHERE s.sales_territory_id = d.sales_territory_id);

-- name: InsertNewVersions :one
-- Passo 3: insere uma versão atual para toda chave da staging que ficou
-- sem versão atual. Isso cobre de uma vez:
--   - chaves novas          (nunca existiram na dimensão)
--   - novas versões         (acabaram de ser fechadas no passo 1)
--   - reativações           (só têm histórico antigo, excluído antes)
-- atuais e historico leem a dimensão como estava ANTES deste INSERT, e são
-- MATERIALIZED para lê-la uma única vez. Sem isso, quando as estatísticas
-- dizem que a dimensão está vazia (p.ex. após TRUNCATE + VACUUM), o
-- planner escolhe Seq Scan da dimensão repetido por linha da staging, e
-- cada repetição percorre também as páginas que este INSERT acabou de
-- gravar: custo quadrático (1 milhão de linhas: minutos em vez de segundos).
WITH atuais AS MATERIALIZED (
    SELECT sales_territory_id FROM dw.dim_sales_territory WHERE is_current
),
historico AS MATERIALIZED (
    SELECT sales_territory_id,
           bool_or(valid_to = now() AND NOT is_deleted) AS fechada_agora
    FROM dw.dim_sales_territory
    WHERE NOT is_current
    GROUP BY sales_territory_id
),
inseridas AS (
    INSERT INTO dw.dim_sales_territory
           (sales_territory_id, region, country, "group", row_hash, valid_from)
    SELECT s.sales_territory_id, s.region, s.country, s."group", s.row_hash, now()
    FROM dw.stg_sales_territory s
    WHERE NOT EXISTS (SELECT 1 FROM atuais a
                      WHERE a.sales_territory_id = s.sales_territory_id)
    RETURNING sales_territory_id
)
SELECT count(*) FILTER (WHERE h.sales_territory_id IS NULL)::int AS novas,
       count(*) FILTER (WHERE h.fechada_agora)::int              AS novas_versoes,
       count(*) FILTER (WHERE NOT h.fechada_agora)::int          AS reativadas
FROM inseridas i
LEFT JOIN historico h ON h.sales_territory_id = i.sales_territory_id;

-- name: InsertEtlLog :one
INSERT INTO dw.etl_log (processo, inicio, fim, linhas_origem,
                        novas, novas_versoes, reativadas, expiradas, excluidas)
VALUES (sqlc.arg(processo), now(), clock_timestamp(), sqlc.arg(linhas_origem),
        sqlc.arg(novas), sqlc.arg(novas_versoes), sqlc.arg(reativadas),
        sqlc.arg(expiradas), sqlc.arg(excluidas))
RETURNING *;

Benchmark

Origem sintética de 10 mil, 100 mil e 1 milhão de territórios. Cada medição é a mediana de 3 execuções de go test -bench, cada uma com 5 cargas. O preparo da origem e o VACUUM ANALYZE de cada carga ficam fora do cronômetro.

  • A versão sem função foi mais rápida nas 9 combinações de tamanho e cenário. Na média geométrica, as regras SCD2 levam 17% menos tempo; a carga completa, 9% menos.
  • A vantagem cresce com o volume nos cenários do dia a dia. Sem mudanças e incremental: 13% mais rápida com 10 mil linhas, 23 a 27% com 100 mil e 24 a 26% com 1 milhão. O MERGE lê a staging duas vezes (UNION ALL) e faz um full join com toda a dimensão; os UPDATEs separados só tocam o que mudou.
  • Na carga inicial a diferença vem da restrição, não da função. No mesmo schema, sem função é 5 a 12% mais rápida. Com o índice único comum no lugar do EXCLUDE DEFERRABLE, que a função exige, a vantagem sobe para 15 a 32%.
  • As idas extras ao servidor não pesaram com o banco local. Num DW remoto com latência alta, cada um dos 4 comandos extras soma uma ida e volta à versão sem função.
  • Foram 3 amostras por medição. O benchstat precisa de 4 a 6 para declarar significância formal. A dispersão ficou abaixo de 5%, exceto no incremental de 1 milhão (cerca de 9%), em que a dimensão cresce de uma carga para a outra.

Defeito encontrado pelo benchmark

Afetava as duas estratégias · corrigido

As duas versões originais tinham uma subconsulta correlacionada sobre dw.dim_sales_territory dentro do comando que grava nessa mesma tabela: o EXISTS que classifica “nova × reativada” no MERGE, e o NOT EXISTS e o EXISTS de InsertNewVersions.

Quando as estatísticas dizem que a dimensão está vazia (depois de TRUNCATE seguido de VACUUM ou autovacuum), o planner executa a subconsulta como um Seq Scan repetido para cada linha da staging. Cada repetição percorre também as páginas que o próprio comando acabou de inserir, e o custo fica quadrático. Uma recarga de 1 milhão de linhas não terminava em 60 s. Depois da correção, leva cerca de 4 s.

A correção lê a dimensão uma única vez, em CTEs MATERIALIZED (historico e atuais), antes de gravar. O cenário inicial do benchmark reproduz exatamente essa situação.
